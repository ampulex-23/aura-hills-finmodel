# AURA HILLS — гайд по финансовой модели

Полное описание расчётного ядра: архитектура, формулы, параметры и принципы.
Источник истины — TypeScript-модель (`src/model/*`); Excel-файл используется
только как оракул для golden-тестов и как формат экспорта.

## Архитектура

Горизонт модели — **72 месяца**: 12 месяцев строительства (с 2027-01) и
60 месяцев эксплуатации (с 2028-01). Расчёт помесячный, одним проходом:

$$\text{Сценарий} \to \text{CAPEX} \to \text{Выручка} \to \text{OPEX} \to \text{ФОТ} \to \text{НДС} \to \text{EBIT} \to \text{CIT} \to \text{P\&L} \to \text{CF} \to \text{KPI}$$

Каждый слой — чистая функция параметров, без скрытого состояния. Все входы —
типизированный JSON (`src/data/params.json`, `scenarios.json`,
`nomenclature.json`, `services.json`), коммитятся в git.

## Выручка

### Аренда банных модулей

Модули продают временные слоты (утро / день 1 / день 2 / вечер). Месячная
ёмкость модуля:

$$S_m = 30 \times \text{слоты/день} \times \text{uptime} \times k_{load}$$

где uptime = 0.95 (~1.5 дня/мес на профилактику), $k_{load}$ — помодульный
коэффициент заполняемости. Проданные слоты:

$$s_m = S_m \times \min(1,\; L_{baths} \times \text{seas}_{baths} \times \text{ramp} \times dm)$$

- $L_{baths}$ — загрузка сценария по году (рамп-ап + рост);
- $\text{seas}$ — сезонность (бани — зимний пик, глэмпинг — летний; Σ = 12);
- $\text{ramp} = \min(1, (k+1)/\text{rampMonths})$ — выход на план;
- $dm$ — мультипликатор спроса (Допущения → Режимы).

Выручка аренды: $s_m \times \bar{p}_m \times g_y$, где $\bar{p}_m$ — цена слота,
взвешенная долями спроса (slotMix), $g_y = (1 + p_{growth})^{\lfloor k/12 \rfloor}$
— годовая индексация цен.

### Ёмкость членов клуба

Члены клуба занимают слоты до платных продаж — вытеснение, а не добавление:

$$\text{слоты}_{члены} = \frac{(\text{мес.члены} + \text{год.члены}) \times \text{визиты/мес} \times \text{гостей/визит}}{\bar{C}}$$

где $\bar{C}$ — средняя вместимость слота. В пиковые месяцы это уменьшает
платную выручку (консервативно), но гости-члены добавляются в гостей F&B.

### Прочие потоки

| Поток | Формула | Примечание |
|---|---|---|
| Парения / массаж | слоты × uptake × цена × гости | доля гостей, берущих услугу |
| Доп. услуги | (uptake − 0.25) × база | как в Excel |
| Глэмпинг | юниты × 30 × загрузка × цена | летняя сезонность |
| Членства | план мес./год. × цена | ramp + рост по сценарию |
| Сертификаты | certsPerMonth × цена | |
| F&B | гости × fbPerGuest | включая гостей-членов |

## OPEX

$$\text{OPEX} = \underbrace{\text{fixed} + \text{IT} + \text{аренда земли}}_{\text{постоянные}} + \underbrace{\Sigma(\text{норма} \times \text{landed}) \times (\text{слоты} | \text{гости} | \text{мес})}_{\text{переменные}} + \underbrace{\%\text{-блок}}_{\text{от выручки}}$$

- **Переменные**: нормы расхода по статьям (веники, дрова, косметика…) ×
  landed cost = цена + max(доставка фикс, цена × %). Индексируются инфляцией.
- **Процентный блок**: эквайринг 2% и ремонт/обслуживание 3% от общей выручки;
  food-cost 35% от выручки F&B; OTA-комиссия 17% × доля OTA-ночей глэмпинга.
- **Постоянные** (с помодульным флагом `perModule` → × числу активных модулей),
  IT-подписки и аренда земли индексируются инфляцией: $\times(1+i)^{\lfloor k/12 \rfloor}$.

## ФОТ

Фонд = оклады штата (`fot.*`, вкладка «Штат») + условные роли: повар (при
`fb.enabled`) и IT-куратор (при `it.enabled`). Оклады индексируются инфляцией
ежегодно; сверху — KPI-бонусы и взносы работодателя 15.15%:

$$\text{ФОТ} = (\text{оклады} \times i_y + \text{бонусы}) \times (1 + 15.15\%)$$

Бонусы = 30% выручки парений + 30% выручки массажа + 1% общей выручки.

## Налоги

- **НДС**: режимы «Гросс» / «С возмещением»; ставки 19% / 9% глэмпинг и F&B;
  входной НДС к зачёту, кредит переносится.
- **CIT 12.5%**: база — EBIT, но с **налоговой амортизацией** (capital
  allowances: конструкции 25 лет, оборудование 7, прочее 5) вместо
  бухгалтерской (10/7/5). Убытки переносятся.
- **Дивиденды**: ЧП × (Σ долей партнёров + УК) с лагом 12 мес. Резервный фонд
  остаётся в компании — не распределяется.
- **SDC 17% + GESY 2.65%** на дивиденды, взвешенные по долям резидентов;
  статус Non-Dom обнуляет оба налога по доле партнёра.

## Cash-Flow

$$\mathrm{FCFF} = \mathrm{ЧП} + \mathrm{аморт.} + \mathrm{CAPEX} + \mathrm{CAPEX}_{отл.} + \mathrm{пресейл} + \mathrm{прогорание} + \mathrm{земля} + \mathrm{preopen}$$

| Строка | Смысл |
|---|---|
| Пре-сейл | Продажа членств/сертификатов последние `presaleMonths` стройки |
| Прогорание | Deferred-режим: пул предоплат прогорает за `presaleRecognizeMonths` без двойного кэша |
| Пул предоплат | Остаток обязательств перед гостями (deferred revenue) |
| Pre-opening | Последние `preopen.months` стройки: оклады+взносы+постоянные/IT вхолостую |
| Аренда земли | Режим `lease`: платёж с 1-го месяца стройки, в операционке — в OPEX |
| CAPEX отложенный | Модуль «Активен» с вводом после открытия платит долю помодульного CAPEX в месяц запуска — real option |

CAPEX = смета × (1 + буфер сценария); земля в режиме `purchase` входит в CAPEX
без амортизации. FCFF дисконтируется: $DF_m = (1 + \mathrm{WACC}/12)^{-m}$.

## KPI

| Метрика | Формула |
|---|---|
| NPV | $\sum_m \mathrm{FCFF}_m \cdot DF_m$ |
| IRR | месячная ставка NPV=0 (bisection) → $(1+r_m)^{12}-1$ |
| Окупаемость | первый месяц с накопл. FCFF > 0 |
| Диск. окупаемость | то же по накопленному DCF |
| MOIC | $\Sigma \mathrm{FCFF}^{+} / \Sigma \mathrm{FCFF}^{-}$ |
| Cash-on-cash | FCFF 3-го года / вложено |
| Пиковая потребность | min накопл. FCFF |
| Break-even | множитель спроса, при котором EBITDA 3-го года = 0 |
| NPV с TV | NPV + $\frac{\mathrm{FCFF}_5(1+g)}{\mathrm{WACC}-g} \cdot DF_{72}$ (опция) |

## Сценарии и анализ

Матрица сценариев (Conservative / Base / Aggressive) задаёт векторы загрузки
по годам, рост цен, буфер CAPEX, длину ramp и uptake доп. услуг. Промежуточные
годы интерполируются как в Excel (y2 между y1 и y3 с весами 20/35, 15/25, 30/70).

- **Sensitivity**: 57 точек реального пересчёта — спрос × WACC, рост цен ×
  буфер CAPEX, уровень всех цен.
- **Tornado**: однофакторный пересчёт 11 драйверов, сортировка по |ΔNPV|.

## Верификация

Golden-тесты сверяют ядро с Excel-оракулом (`formulas`) по 3 сценариям с
точностью Δ < 0.01%; слои, которых нет в книге (F&B, IT, preopen, члены-слоты,
GESY, налоговая амортизация, OTA, TV), в тестах выключаются для паритета.
10/10 тестов зелёные — CI перед каждым коммитом.

## Хранение и persistence

Правки UI сохраняются в localStorage (debounce 400 мс) поверх JSON-дефолтов.
При обновлении модели недостающие поля старых снапшотов добираются из
дефолтов рекурсивно (`fillDefaults`) — пользовательские значения не теряются.
«Сбросить» возвращает полный дефолт; JSON export/import — полный снапшот
параметров, сценариев и справочников.
